# CODEBUDDY.md

This file provides guidance to CodeBuddy Code when working with code in this repository.

## What this repository is

`filters.trade` is an R package that selects trading instruments by applying
named, saved filter expressions. It is a deliberate port of the CRAN
[`filters`](https://cran.r-project.org/package=filters) package (authored by
Thomas Neitmann, maintained by Joe Zhu) from the clinical trial domain to the
trading domain: where `filters` selects subjects out of CDISC datasets like
`ADSL` and `ADAE`, `filters.trade` selects trading codes out of datasets like
`TICKERS` and `PRICES`.

It is one half of a pair. The sibling directory `autoslider.trade` is planned
as a downstream package of `autoslider.core` that produces tables and figures
for finance trading. `filters.trade` is intended to select the instruments
those outputs are computed on.

`inst/design.md` is the design document: purpose, scope, and the requirements
the package meets, written with Rupp obligation keywords — **shall** for what
must hold, **should** for what is desirable, **will** for what is explicitly
optional. Read it before changing behaviour, and update it when scope changes.
Fetching market data, computing indicators, backtesting and rendering output
are all out of scope there.

## Commands

Run from the repository root. R 4.6.1 is available under WSL with `devtools`,
`usethis`, `roxygen2`, `testthat` and `yaml` installed. `lintr` is not
installed yet.

| Step | Command |
| --- | --- |
| Iterate during development | `Rscript -e 'devtools::load_all()'` |
| Regenerate `man/` and `NAMESPACE` | `Rscript -e 'devtools::document()'` |
| Run all tests | `Rscript -e 'devtools::test()'` |
| Run one test file | `Rscript -e 'devtools::load_all(); testthat::test_file("tests/testthat/test-filters.R")'` |
| Run test files matching a name | `Rscript -e 'devtools::test(filter = "load_filters")'` |
| Run one test block | `Rscript -e 'devtools::load_all(); testthat::test_file("tests/testthat/test-filters.R", desc = "apply_filter subsets a data frame")'` |
| Lint | `install.packages("lintr")`, then `Rscript -e 'lintr::lint_package()'` |
| Full check | `Rscript -e 'devtools::check()'` |
| Build source tarball | `Rscript -e 'devtools::build()'` |
| Install | `Rscript -e 'devtools::install()'` |

Shell equivalents of the last three: `R CMD build .`, then
`R CMD check filters.trade_*.tar.gz`.

The `desc` argument of `test_file()` must be the complete `test_that()`
description, not a substring; a partial match errors with "Failed to find test
with description" rather than silently running nothing.

`load_all()` is preferred over `install()` while developing: it is faster and
exposes unexported objects, which the tests rely on.

`NAMESPACE` and `man/*.Rd` are generated by roxygen2 from the `#'` blocks.
Edit the roxygen comments and re-run `devtools::document()`; never edit the
generated files by hand. Whether a function is exported is decided solely by
`@export`.

## Architecture

### One registry, two ways in

The whole package hangs off a single environment, `.filters`, created in
`R/package.R`. It lives for the length of the R session and is never persisted
to disk. Each entry is keyed by an upper case `id` and holds
`list(title = , target = , condition = )`, where `condition` is an *unevaluated*
language object.

There are two entry points, and they converge on the same stored shape:

- `add_filter()` — `condition` is captured with `substitute()`, so it is
  written unquoted. With `character_only = TRUE` it is `parse()`d from a
  string instead.
- `load_filters()` — reads a yaml file where each top level key is an `id` and
  calls `add_filter(..., character_only = TRUE)`.

Because both paths end up storing a language object, a filter defined in yaml
and one defined in code are indistinguishable downstream. Preserve that
symmetry when changing either path.

### From id to subset

`get_filters()` splits a combined id on underscores, so `"US_LARGECAP"` is
shorthand for the two filters `US` and `LARGECAP`.

`apply_filter()` is an S3 generic with three methods, all in `R/filters.R`:

- `apply_filter.data.frame()` — keeps only the definitions whose `target`
  matches the dataset, combines their conditions with `&` via
  `combine_filter_conditions()`, and evaluates them by constructing and
  evaluating a `subset()` call. If no definition targets the dataset, the data
  is returned unchanged with a message. `target` defaults to
  `toupper(deparse(substitute(data)))`, i.e. the *variable name*, so passing
  `target =` explicitly is clearer and safer.
- `apply_filter.list()` — filters each named dataset, then propagates the
  selection (see below).
- `apply_filter.default()` — errors, so unsupported classes fail loudly rather
  than silently passing through.

### The trading conventions

Two conventions carry the domain meaning and are the main departure from
`filters`:

- `SYMBOL` is the column holding the trading code — `code_col()` in
  `R/utils.R`, overridable with `options(filters.trade.code_col = )`.
- `TICKERS` is the dataset holding the master list of trading codes —
  `code_dataset()`, overridable with `options(filters.trade.code_dataset = )`.

`restrict_to_selected_codes()` is the trading counterpart of
`remove_subjects_not_in_adsl()` in `filters`: once `TICKERS` has been filtered,
every other dataset in the list is restricted to the codes that survived, so a
selection made on the universe carries through to prices and signals. Where
`filters` semi-joins on `STUDYID` + `USUBJID`, this package joins on the single
trading code column.

## Conventions and invariants

- Filter ids must match `^[A-Z0-9]+$`. Lower case, spaces and punctuation are
  rejected by `assert_valid_id()`. Use SCREAMING_SNAKE_CASE style names.
- `target` is upper cased on the way in, and dataset names are upper cased
  before matching, so `target = "tickers"` and `target = "TICKERS"` are the
  same filter.
- Filter conditions are evaluated inside a `subset()` call, so columns are
  referenced unquoted. A condition is not a function and cannot be passed
  around as one.
- `add_filter()` refuses to redefine an existing id unless `overwrite = TRUE`.
- **The registry is session-global and tests share it.** Give every test its
  own ids and pass `overwrite = TRUE`, otherwise tests pass alone and fail
  together. This is the most likely cause of an otherwise baffling test
  failure.
- `deparse()` is deliberately redefined in `R/utils.R` to swap `"` for `'`,
  matching `filters`. Inside package code, `deparse()` is *not*
  `base::deparse()`; use `base::deparse()` if the base behaviour is needed.
- Linting is configured by `.lintr`, which disables the object name, usage,
  indentation, `seq`, vector logic and commented code linters, and allows
  120 character lines. Follow it rather than the lintr defaults.
- Documentation is generated with roxygen markdown enabled
  (`Roxygen: list(markdown = TRUE)` in `DESCRIPTION`).
